# GridPilot-AGH N-1 安全性审查与项目改进计划

> 审查日期：2026-10-02  
> 审查对象：`output/normal/results.json`、当前 N-1 校核、约束生成、不确定性分析与网页展示实现

## 1. 先给结论

当前 N-1 模块的**程序运行和统计逻辑基本正常**，但当前正常场景的结果**不满足严格意义上的 N-1 安全要求**。

- 24 小时基态 AC 潮流正常：0 个基态越限时段；
- N-1 已检查完整 24 小时，共 `24 × 32 = 768` 个线路退出工况；
- 新增独立备用馈线 `B1-2` 后，`L1-2` 的24个根部故障工况均可在10分钟切换假设下恢复供电，恢复后失供为0；
- 迭代 SCOPF 前有475个安全、293个不安全，安全率 **61.85%**；
- 三轮迭代共生成并应用12条高风险约束，最终有498个安全、270个不安全，安全率提高到 **64.84%**；
- 270个不安全工况均为恢复后的低电压，0个失供、0个线路过载、0个AC潮流不收敛；
- 综合风险指数从8067.4降至7328.8，下降 **9.16%**，高风险工况减少23个；
- 最终最差最低电压为 **0.86806 pu**，仍低于项目设置的0.95 pu下限，因此尚未达到严格 N-1 全通过。

因此应该把当前结论表述为：

> 基态调度安全，备用馈线解决了 `L1-2` 根部失供，三轮迭代 SCOPF 和事故后资源响应已使全日风险明显下降；但仍有270个低电压工况，当前版本仍是风险识别与决策支持原型，不能表述为“严格 N-1 全通过”。

不应表述为“系统已经通过 N-1 校核”。

## 2. 64.84% 的统计口径

### 2.1 统计口径

当前安全率计算为：

```text
安全率 = 安全工况数 / 已枚举工况数
       = 498 / 768
       = 64.84%
```

一个工况必须同时满足以下条件才被计为安全：

1. pandapower AC 潮流收敛；
2. 故障恢复后没有失供负荷；
3. 所有节点电压均在 0.95～1.05 pu；
4. 所有线路负载率不超过 100%。

每条运行线路退出后，程序会比较“不恢复”、5条常开联络线和1条独立备用馈线的可行恢复结果，并选择风险最低的单支路纠正方案。因此当前指标更准确的名称应为：

> **全24小时线路 N-1 + 最佳单支路纠正恢复通过率**

它不是故障概率，也不是全日可靠性指标。

### 2.2 主要失败原因

| 类型 | 数量 | 解释 |
|---|---:|---|
| 恢复后低电压 | 270 | 联络线恢复了供电，但供电路径变长、阻抗增加，末端电压仍低于0.95 pu |
| 大范围失供 | 0 | `L1-2` 根部故障由独立备用馈线 `B1-2` 临时转供，24个时段均恢复成功 |
| 线路过载 | 0 | 当前工况的主要瓶颈不是热稳定容量 |
| 潮流不收敛 | 0 | 本轮所有 AC 工况均能得到数值解，说明统计结果并非由求解失败造成 |

这说明当前 N-1 结果在物理上是可以解释的，并不是简单的页面显示错误。

## 3. 当前结果“正常”到什么程度

| 判断问题 | 结论 | 说明 |
|---|---|---|
| 代码是否真的执行了 pandapower AC N-1 | 是 | 逐线退出，并对无恢复、5条联络线和独立备用馈线的可行方案运行AC潮流 |
| 768 个工况数量是否合理 | 是 | 24 个时段分别枚举 32 条运行线路 |
| 64.84% 是否是程序算错 | 暂未发现 | 498/768与结果文件一致，失败分类也能与电压记录对应 |
| 64.84% 是否满足工程 N-1 要求 | 否 | 若目标是“任一可信单元退出后仍无越限、无失供”，则应接近100% |
| 当前安全率能否代表全天 | 可以代表当前24小时算例 | 但仍取决于该日曲线、可信故障集合和单支路恢复假设 |
| 当前安全率能否跨场景直接比较 | 不建议 | 不同场景检查时段数可能不同，而且主动削负荷会让线路和电压风险看起来降低 |
| 12条安全约束是否带来改进 | 是，但未完全解决 | 三轮后失败数293→270，风险指数下降9.16%，仍有270个低电压工况 |

## 4. 当前 N-1 实现需要立即修正的地方

### P0-1：把约束目标改成真实安全阈值

当前生成的电压约束采用“原最低电压 + 0.005 pu”的渐进目标，并且最高不超过 0.95 pu。例如原工况最低电压为 0.864 pu 时，下一轮只要求约 0.869 pu。

这可以降低风险分，但不能把工况变成安全工况，也是“风险指数下降、失败数量不变”的主要原因。

建议：

- 最终约束统一要求事故后电压不低于 0.95 pu；
- 若直接要求 0.95 pu 不可行，引入带高惩罚的电压松弛变量；
- 明确输出“安全可行”“带松弛可行”“结构性不可行”三种状态；
- 采用多轮约束生成，直到没有新增违规工况或达到迭代上限；
- 页面同时显示违规量，例如最低电压距离 0.95 pu 还差多少，而不只显示风险分。

验收标准：可恢复故障的最低电压全部达到 0.95 pu；未达到时必须明确显示不可行量，不能标为安全。

### 已完成：全 24 小时 N-1；下一步统一比较口径并优化性能

当前默认模式已经完成24小时全量枚举。后续建议保留两种模式：

- 快速演示：3 个关键时段；
- 完整评估：24 小时 × 32 条线路 = 768 个工况。

不同场景必须使用相同的时段集合和相同的可信故障集合，否则安全率不能直接比较。

当前已验收24个时段、32条线路和768条唯一记录。下一步应增加结果缓存、并行计算和统一场景分母。

### P0-3：把“单联络搜索”升级为网络重构优化

当前只允许从 5 条联络线中选择一条闭合，无法联合操作分段开关，也不能寻找多开关的最优恢复拓扑。

建议建立 MILP 或 MISOCP 重构模型，至少包含：

- 故障线路强制断开；
- 分段开关与联络开关二进制状态；
- 节点带电状态与负荷恢复变量；
- 单电源径向性或生成树约束；
- 连通性约束；
- 线路容量和节点电压约束；
- 最大恢复负荷目标；
- 开关动作次数和操作成本惩罚。

验收标准：所有恢复拓扑无环、故障段隔离、所有带电节点连接到电源，且恢复负荷不低于当前单联络方法。

### 已完成 P0-4：用独立备用馈线处理 `L1-2` 根部故障

`L1-2` 退出后原有联络线无法连接到第二电源，因此这不是优化器仅通过调整储能功率就能解决的问题。当前版本已经新增正常开路的独立备用馈线 `B1-2`：主馈线故障隔离后将其合闸，24个根部故障时段均恢复全部负荷，且恢复拓扑保持32条边、全节点连通和辐射结构。

当前实现与后续可选方式：

1. **已实现**：在模型中增加独立备用馈线，并在拓扑图中用青色双线标出；
2. 配置具有成网能力的储能/微电网，并增加孤岛功率平衡约束；
3. 将 `L1-2` 明确标记为规划级结构性风险；
4. 若比赛口径允许排除母线出口故障，必须在“可信故障集合”中公开说明，不能静默排除。

验收结果：`L1-2` 的24个工况均选择 `B1-2`，恢复后失供为0；页面同时显示1分钟隔离、10分钟备用馈线切换和3小时物理抢修假设。

### 已完成：故障恢复与物理抢修分时标识

日前24小时 N-1 是对每个时段分别施加一次假想故障，并不表示同一天一定连续发生32个故障。当前版本将两个时间尺度分开：

- 保护隔离：默认1分钟；
- 联络线临时转供：默认5分钟；
- 独立备用馈线临时转供：默认10分钟；
- 故障元件物理抢修：默认3小时，且可在数据文件中配置。

3小时适合作为“城市、可到达、简单线路故障”的演示目标，但不是统一工程保证值。地下电缆开挖、设备更换、恶劣天气或道路许可等情形可能需要更长时间。系统在临时转供后继续带电运行，物理抢修完成后再恢复常态拓扑。

### P0-5：分开报告故障前、恢复前和恢复后三种状态

当前最终安全率直接使用最佳联络线或备用馈线恢复后的结果，容易让读者误以为系统在故障瞬间就保持供电。

建议分别给出：

- 故障瞬间失供量；
- 恢复操作后的剩余失供量；
- 恢复前后最低电压和最高线路负载率；
- 所需开关动作数；
- 假定恢复时间；
- 未恢复电量 ENS。

验收标准：页面和 JSON 对每个工况都保存 before/after 指标，并能计算恢复收益。

## 5. 整个项目的进一步改进方向

### 5.1 优化模型与安全校核

| 优先级 | 改进项 | 当前不足 | 建议实现 | 验收指标 |
|---|---|---|---|---|
| 已完成 P0 | 真正的迭代 SCOPF | 已执行三轮“N-1筛选—加约束—重求解—AC复核” | 每轮最多新增4条，累计应用12条约束 | 高风险工况293→270，逐轮结果可追溯 |
| 已完成 P0 | 事故后资源响应 | 已加入独立事故后纠正变量 | 储能有功/无功、需求响应和上级电网备用均受容量约束 | 页面逐故障显示纠正动作；典型约束启用约7.27 kW需求响应和21.81 kvar无功修正 |
| P1 | SOCP/AC-OPF | LinDistFlow 与 AC 潮流之间仍有偏差 | 增加 SOCP DistFlow，必要时使用 AC-OPF 作基准 | 优化预测电压与 AC 复核误差可量化且受控 |
| P1 | OLTC 和无功设备 | 低电压只能靠有功调度缓解 | 增加 OLTC、电容器、SVG 和逆变器无功优化 | 低电压工况显著减少，控制动作物理可执行 |
| P1 | 三相不平衡 | 当前采用三相平衡稳态模型 | 使用三相潮流，增加单相负荷和相间不平衡 | 输出各相电压、电流和不平衡率 |
| P2 | 保护与暂态 | 当前仅覆盖稳态潮流 | 增加短路电流、保护配合和开关时序校核 | 恢复动作不违反保护逻辑，关键场景通过动态验证 |

### 5.2 不确定性模块

当前界面能生成 20 个相关场景、扇形图、直方图、CVaR 和策略对比，适合演示；但需要注意：当前所谓“两阶段随机优化”和“鲁棒优化”本质上还是**对预设备用策略的场景评估和参数搜索**，还不是完整的两阶段随机调度模型。

建议：

1. 第一阶段决定日前购电、储能计划和备用容量；
2. 第二阶段为每个场景设置光伏弃电、负荷削减、储能修正和购电偏差变量；
3. 加入非预见性约束；
4. 将期望成本和 CVaR 直接放入统一优化目标；
5. 鲁棒版本建立明确的不确定集合，而不是直接取样本最大偏差；
6. 用真实历史残差校准分布、时间相关性和交叉相关性；
7. 增加样本外测试，避免只在生成场景上比较方法。

验收标准：报告能展示第一阶段决策、各场景第二阶段修正、目标函数和约束规模；“随机优化”标签与实际数学模型一致。

### 5.3 数据可信度

当前负荷、光伏、电价和误差参数主要为项目内置模板，应进一步增加：

- 数据来源、许可证、时间范围、采样间隔和预处理说明；
- IEEE 33 节点参数版本与基准容量说明；
- 线路额定电流和联络线容量的依据；
- 光伏与储能接入位置选择依据；
- 训练集、校准集和测试集划分；
- 每次运行的输入快照、随机种子、软件版本和求解器版本。

可以接入公开配电网和时序数据，但比赛演示中应保留一套固定、可复现的小数据集。

### 5.4 指标体系

不建议只用“安全率”一个指标。建议同时报告：

- 严格 N-1 通过率；
- 未恢复负荷和未供电量 ENS/EENS；
- 最低电压、最大电压偏差和越限持续时间；
- 最大线路负载率；
- 故障恢复率；
- 平均开关动作数；
- 结构性不可恢复工况数；
- 风险加权指标：故障概率 × 后果；
- 基态成本、安全约束成本和可靠性收益。

“主动削负荷后安全率提高”的场景必须同时突出显示失供电量，避免把降级运行误解为更安全。

### 5.5 Agent 与工程闭环

建议将当前整体流程进一步拆成可审计工具：

1. 数据校验；
2. 概率预测/场景生成；
3. 基态滚动优化；
4. AC 潮流校核；
5. N-1 筛选；
6. 安全约束生成；
7. 网络重构优化；
8. 复核与报告导出。

Agent 应只负责选择工具、参数和迭代策略，电网安全判据仍由确定性的专业模型与校核器执行。真实执行模式需要人工审批、权限控制和完整审计日志。

### 5.6 测试、文档和部署

建议补充以下自动化测试：

- 每条 N-1 记录都能还原对应网络；
- 恢复拓扑无环且连通；
- 故障线路始终断开；
- 安全标签与电压、热稳定和失供判据完全一致；
- 全 24 小时 N-1 的工况数量固定为 768；
- 安全约束加入后不能让目标工况变得更差；
- LinDistFlow 与 pandapower 电压误差有上限；
- 随机场景在相同种子下可复现；
- 页面上的数字与 JSON 原始结果一致。

同时需要更新 README 的“模型边界”。当前 README 仍有“线路 N-1 尚未嵌入滚动调度约束、尚未覆盖概率预测”的旧描述，与现有实现不一致。

## 6. 推荐实施顺序

### 第一阶段：把 N-1 结果做实

1. 统一安全率分母和故障集合；
2. 将电压约束目标改为真正的 0.95 pu；
3. 已完成三轮约束生成；下一步显示不可行松弛并扩展到收敛停止；
4. 分开报告故障前、恢复前和恢复后指标；
5. 为768工况增加并行计算与结果缓存。

这一阶段完成后，项目才能明确回答“哪些故障真正达标、哪些故障物理上不可修复”。

### 第二阶段：提升技术深度

1. MILP/MISOCP 网络重构；
2. 事故后储能、需求响应、无功和 OLTC 协同控制；
3. 真正的两阶段随机优化与 CVaR；
4. 真实历史残差和样本外验证。

### 第三阶段：提升工程可信度

1. 三相不平衡潮流；
2. 保护、短路和开关动作时序；
3. 多时间尺度调度；
4. 标准数据、版本快照、容器部署和审计机制。

## 7. 下一版本建议的量化验收目标

建议将下一版本定义为“安全约束与不确定性联合增强版”，至少达到：

- 基态 24 小时 AC 潮流全部收敛且无越限；
- 已完成：768 个全日线路 N-1 工况，并验证24个时段、32条线路和768条唯一记录；
- 所有可恢复工况满足电压不低于 0.95 pu、线路负载率不超过 100%；
- 已完成：`L1-2` 通过独立备用馈线恢复，拓扑和修复时间轴均可视化；
- 相比当前版本，可恢复高风险工况数量下降至少 50%；
- 每个恢复方案满足故障隔离、连通性和径向性；
- 随机优化采用显式第一阶段/第二阶段变量和非预见性约束；
- 所有结果可由固定配置、随机种子和软件版本复现；
- 网页能够在 30 秒内让评委看懂“发现故障—生成约束—重新优化—恢复拓扑—AC 复核”的完整闭环。

## 8. 最适合比赛答辩的表述

可以这样介绍当前系统：

> GridPilot-AGH 已经具备基态滚动优化、pandapower AC校核、全24小时线路N-1枚举、独立备用馈线恢复、三轮迭代SCOPF和事故后资源响应能力。正常场景中，`L1-2` 根部故障的24个时段均由 `B1-2` 恢复，迭代后N-1通过率由61.85%提高到64.84%，高风险工况由293降至270，综合风险下降9.16%。系统仍如实保留270个低电压工况；下一阶段将通过严格0.95 pu安全约束、网络重构和真实两阶段随机优化进一步提升安全性与研究深度。
